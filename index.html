Philosophy产品理念

AI 已经进了校园，
还没有进入学习过程。

学生卡住时会去问 AI，但那发生在教学活动之外：教师看不到，系统记不下，考核也管不着。循阶把这几个缺口逐条接回教学场景。

断点

在教学活动之外

AI 停在教学活动之外，遇到问题由学生自行寻求帮助。

接回之后

在学习过程之内

把 Agent 放进学习过程本身：它会主动提示、推进、提问，学生在学习知识的同时，也练习如何与 AI 沟通、协作、做好人机协同。

断点

同一份作业发给全班

传统班级教学里，个性化学习需求难以被真正满足。

→

接回之后

画像持续维护，规划随之调整

Agent 持续从交互中提取学习画像信号并维护更新，学习规划随画像动态调整；画像不是黑箱，学生可以查看并纠正其中不符合自己的判断。

断点

一次分数定结论

完成任务不一定是真的会。只看到最终提交的那一份，一次分数越来越难回答「这个学生到底会不会」。

→

接回之后

作品 + 过程记录 + 教师判断

主动把 AI 拉进评估场景：用 Agent 引导下的个性化真实项目替代「标准答案」式作业，追问、提示、自测、动手验证全程留痕，作品与过程记录共同构成教学判断依据。

断点

一句话就能拿到答案

一句话就能拿到答案，学生不再愿意追问和思考；要提问，得先克服找老师的阻力。

→

接回之后

点到为止，引导强度自己定

教育场景下的交互设计区别于普通对话式 AI：不把话说完、不把任务一步做到位，点到为止；同时减小学生提问的阻力，引导强度由学生自己设定。

断点

标准答案式习题

课后教学测验形式单一，教师想做交互式载体却成本高。

→

接回之后

个性化真实项目 + 学科工具包

学科工具包打包各课程常用工具与产物，可复用、可共享、按需安装；Agent 还能按当前教学需要动态生成补充交互，教师不必先成为前端工程师。

断点

课内知识与真实场景脱节

AI 快速发展，学生开始怀疑「现在学的东西毕业还有没有用」。

→

接回之后

在真实项目里边做边学

把课内知识延伸到真实任务与真实项目。原本望而却步的场景，在 Agent 陪同下可以边做边学，能力边界被实际推开。

02 / 04

把话说一半，剩下的让学生走

对话页是纯单列对话流加输入框。一个回合有明确状态：等待首 token、思考中、正文流出、落定后的操作条。思考过程落定后折叠成「已思考 N 秒」，默认收起。

  • 消息内教学卡：追问选项（点击直发）、概念讲解（含时序波形）、自测小测
  • 引导气泡与交互卡可收纳进所属任务的卡片体系；归属由 Agent 建议、学生确认
  • 模型与思考强度可选，上下文以进度环显示；停止保留半截内容并可继续生成

写、烧、看它动起来

进入任务即沉浸模式：侧栏滑出，工作区占满屏幕。52px 指挥栏承载工具标签、任务进度环、运行状态与版本流；中心工具区像浏览器标签一样可分屏拖拽，布局按任务持久化。

  • 虚拟开发板可操作：拨开关、按按钮，观察 LED 与数码管按装载版本响应
  • 版本流写明「草稿 v4 ▸ 板载 v3」，烧录后变为「✓ 板载 v4 · 与草稿同步」
  • Agent 引导气泡可固定为右栏对话；未覆盖的课程显示「工具包接入中」
04 / 04

两个方向的对偶设定

学生画像是「Agent 眼中的我」：能力雷达、特征标签、擅长与待加强，由教学 Agent 维护并标注更新时间。Agent 个性化是「我眼中的 Agent」：称呼、引导强度、提示方式与语气，由学生直接修改。

  • 画像里任何一条不符合自己的判断，都可以点「这不准」纠正
  • 引导强度是一条从「多问引导」到「直接给答案」的滑杆
  • 数据与隐私独立成页：可导出、可清除缓存、可重置布局

The loop学习闭环

一个项目任务，
怎样从教师手里回到教师手里。

01

教师布置项目任务

任务要求关联完成所需的材料、虚拟物件与学科工具包。Agent 可辅助准备测验设计，但教学设计与判断由教师主导。

02

学生在引导下动手做

围绕任务开展个人项目：追问、提示、自测、写代码、虚拟烧录、观察板卡响应。每一步交互都进入学习过程记录。

03

过程回流教学判断

Agent 收集、归纳、分析数据指标与日志，教师查看作品与学习过程并给出反馈，据此调整教学计划——闭环合上。

过程记录回流 · 回到教师手里

贯穿始终的是同一件事：Agent 从辅助教师设计，到引导学生动手，再到分析教学状态，而不是替谁完成作业。

仿真引擎路线，已在本机实测跑通

2026-10-11 的可行性调研在 macOS arm64 上把两条路线都做到了可复现原型，并明确建议：不要退化成纯 mock 或前端自算。

  • 桌面引擎路线

    Icarus Verilog + VPI 双向交互，8/8 因果性断言通过，数码管多位扫描 5/5 通过；引擎自包含 6.5 MB、可重定位、无需依赖 PATH。

  • 纯浏览器路线

    Web-first（yosys WASM + DigitalJS）同套 8/8 断言通过，许可证全部 permissive。

  • 实测性能

    步进吞吐 145 万–186 万 周期/秒；界面与引擎往返 0.010 ms；22 项语言构造探针。

尚未决策 / 未验证

跨平台打包（Windows 风险最高，Icarus 官方无预编译二进制）、GPL / LGPL 合规边界、真实浏览器环境与大规模设计的吞吐验证。

FAQ常见问题

几个一定会被问到的问题。

通用对话以「给出答案」为终点，循阶以「学生学会」为终点。差别落在交互设计上：Agent 不把话说完、不把任务一步做到位，用追问选项、概念卡和自测卡一次推进一小步；同时它会主动提示与提问，减小学生开口的阻力。所有交互都进入学习过程记录，供教师判断。

这是引导强度要解决的问题，而且它由学生自己在 Agent 个性化里设定：一端是「多问引导」，另一端是「直接给答案」。教学设计的取舍仍由教师主导——Agent 不是自动答题器，也不是最终评分者。

教师负责项目任务的布置与教学判断：定义任务要求、关联材料与工具包，之后查看作品与学习过程记录并给出反馈。教学测验的设计与数据分析由 Agent 辅助，但判断权不交给系统。首版是个人项目形态，教师后续查看过程并反馈。

方向是本地优先：项目、工具执行、仿真与学习记录优先留在学生电脑，以降低远程服务器依赖与成本（ADR-0001 已接受）。AI 能力通过模型 API 获取，不要求本机运行大模型。数据与隐私在设置页独立成页，支持导出与清除缓存。

不支持。首版聚焦学生本地桌面 Agent，兼容 Windows 与 macOS；手机端明确不在当前范围内。项目、动手操作与仿真都需要真实的桌面工具体验。

当前可运行的是学生端前端基线：四个页面与交互完整，数据由模拟适配层提供，用于打磨交互；桌面宿主、真实 Agent 与后端连接仍在推进。本页所有界面均为设计还原示意。若你打算把课程项目接入试点，欢迎通过下方方式联系我们。
